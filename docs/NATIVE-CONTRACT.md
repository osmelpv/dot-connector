# Native terminal reader contract (simulation only)

`src/native-reader.mjs` is an isolated provider contract. It does not call Windows, load UI Automation, install dependencies, or register a new MCP tool. The existing MCP transport and terminal profiles are unchanged. A Windows built-in or FlaUI provider can implement the same two methods after source/dependency review and approval of the runtime path. The Windows/.NET provider now has compiled but unexecuted source; see [its audit and runtime gates](NATIVE-PROVIDER.md). No live provider is connected.

The operator must identify and authorize one terminal target before binding it. The target contains an exact decimal HWND, PID, process start-time ticks, and a UIA ancestry path made of runtime-ID arrays. The provider must resolve every ancestor within that exact HWND, reject ambiguity, and verify PID/start time against the actual process. It must not enumerate text from other windows or select a replacement element by a similar name. Runtime IDs are session-local identities, not reusable cross-launch selectors.

Provider methods:

- `observe({target, identityOnly:true})`: return `{target, capturedAtMs, foregroundHwnd, focusedPanePath}` after querying the actual target and current focus. Do not simply echo requested identity. Return no terminal text here.
- `getVisibleRanges({target, maxRanges:64, maxCharacters:16000, source:'TextPattern.GetVisibleRanges'})`: use that exact UIA API and return `{target, capturedAtMs, source, ranges:[{text, visible:true}], truncated}`. Enforce limits inside the provider before materializing or transmitting text. Preserve provider range order and exact text; mark truncation honestly. No `DocumentRange` fallback and no full-history read followed by trimming.

Timestamps are milliseconds on the adapter's current clock and must describe newly collected evidence. Stale or future observations fail. The adapter checks identity and focus before and after the visible read, rejects excessive counts/aggregate text, invalidates older snapshots, and allows no overlapping read queue. Errors from provider invocation are sanitized; do not log captured terminal content or raw exceptions. The reader now requires NativeWorkerSupervisor outside explicit simulation mode. The supervisor enforces a per-call deadline (at most 5 seconds), terminates only its own worker process, and settles after process close. If close is not confirmed within 250 ms, it reports unconfirmed cleanup and permanently disables further calls. Deadline and explicit cancellation are tested against owned stalled Node fixtures in WSL, not a UIA host. No actual native host/codec bridge exists yet; native integration remains disabled. A worker must not create descendants: no process-tree kill capability is claimed. Arbitrary in-process providers are accepted only with simulation:true and have no timeout guarantee.

Input is unavailable unconditionally, including after an enable signal. Focus mismatch aborts; it never activates a window. No global keyboard hooks, SendInput, elevation, integrity-level changes, network access, or credential storage are included. A future provider must preserve UIPI/UAC and report inaccessible targets instead of elevating or bypassing them. Check-before/after cannot detect a transient focus switch that switches back, and UIA visibility does not prove pixels are unobscured by other windows. Human typing detection and exclusive control are not claimed.

Tests use only JavaScript fake providers. They verify binding changes, focus changes, freshness, visible-only provenance, bounded responses, disabled input, sanitized failures, and concurrency. These results are **not evidence of a real Windows Terminal read or write**. The provider declaration of visible origin and its identity observations are trusted boundaries; schema validation cannot prove a provider is honest.

Next gate: finish third-party review before restoring or installing anything; obtain a supported UIA runtime; have the user identify a target or announce an empty dedicated test window; then compare a bounded real visible-range read with known visible content. Do not advertise native capability or expose native MCP tools until that test succeeds. Source and dependency audit must precede real execution.

## Numeric and text boundaries

HWND and start-time ticks are canonical positive decimal strings at most Int64.MaxValue (9223372036854775807); PID is a positive Int32. Limits are UTF-16 code units, matching JavaScript string length and C# String.Length. Valid surrogate pairs are preserved. Lone low surrogates and interior or unexpected trailing high surrogates fail closed. Only the last truncated range may drop one trailing high surrogate; truncation remains explicit and no replacement character is inserted. Split surrogate pairs across separate provider ranges are rejected rather than guessed.

Identity in the text response and capture freshness after the final identity observation are independently checked. These tests, and simulated Unicode responses, do not verify native UIA behavior.
