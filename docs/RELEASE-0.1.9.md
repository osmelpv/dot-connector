# 0.1.9 experimental release

Adds bounded operation metadata logs, a local tarball installer for Linux projects, and a verified WSL-to-Windows metadata bridge. Local validation includes diagnostic status/logs during an active session, session exclusion, normal closure and a real Windows MCP metadata handshake with target null and nativeCalls false. The prepared helper is an explicit external dependency. New Windows preparation requires separate consent when script policy blocks it; no automatic policy override is included.

Focusless console control remains unavailable. The isolated C# prototype passed 97 fake assertions, and the pure registration model always returns blocked. No public resolver sufficient to bind an arbitrary Windows Terminal pane/client/console/WSL tty was identified. Console inheritance from a WSL-launched helper may refer to another ConPTY. A cooperative shell would not control an already-running OpenCode/TUI. Real end-to-end WSL terminal reading/writing remains pending; no input capability is enabled by this release.

Verification before publication: 92 JavaScript tests, build, package checks, independent source/documentation review and fake-only x64 compilation. No remote CI is configured for this release: the newly proposed workflow was explicitly excluded from publication by the user. Local verification scripts and tests are retained. No GUI, real console attachment or AI-provider calls were part of the local suite. License remains UNLICENSED and package private; there is no npm registry publication.

Compatibility note: source inventories now include the isolated native-console-prototype.cs. Older managed updaters with a narrower source allowlist may reject this release before preparation. Such rejection must remain fail-closed; do not remove locks, patch an installed updater or weaken validation to force an upgrade. The existing consumer's pinned update result must be reported separately from publication success. Old stable launchers also do not acquire newer metadata-concurrency behavior automatically.

Assets include source archive, update manifest, package tarball and checksums. SHA-256 establishes integrity under publisher/GitHub trust, not an independent signature. Public distribution does not grant an open-source license. Publishing does not select a terminal, create grants, reset claims or modify application projects.
